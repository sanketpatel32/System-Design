# Architecture Archaeologist — Implementation Plan

Build the **full "Ghost Orders at Midnight" MVP** as an isolated feature inside the existing static-export Next.js app, following the spec's mandated phase order. Mode A (frontend-only). Vitest + Zod added as dev/runtime deps.

## Repository mapping (spec §7.2 → repo conventions)

| Spec layer | Repo location | Rationale |
|---|---|---|
| `domain/` | `lib/game/domain/**` | Pure TS, no React — matches `lib/content.ts`, `lib/progress.ts` style |
| `application/` | `lib/game/application/**` | Session/case orchestration services |
| `infrastructure/` | `lib/game/infrastructure/**` | localStorage adapter mirroring `lib/progress.ts` (`atlas:` namespace → `atlas:game:...`) |
| `content/cases/` | `lib/game/content/cases/ghost-orders-at-midnight/**` | `.ts` modules (not JSON) for type-safe static bundling + Zod validation at load |
| `ui/pages/` | `app/game/**` | App Router route |
| `ui/components/` | `components/game/**` | Matches `components/flashcards/`, `components/topic/` pattern |
| `ui/hooks/` | `lib/game/hooks/**` | `useReducer` + persistence hook |
| `tests/` | `lib/game/**/*.test.ts` (colocated) + `tests/game/` for integration | Vitest |

`@/*` path alias + existing Tailwind content globs (`./app/**`, `./components/**`, `./lib/**`) already cover all new files — **no Tailwind/config change required**.

## Phase 7 — Deterministic simulation engine (the core)
All pure functions in `lib/game/domain/simulation/`:
- `seeded-rng.ts` — Mulberry32; seed = hash of `caseId + sessionId + runNumber + architectureHash`; **no `Math.random()`**
- `traffic-model.ts` — 60s cohort timeline (warm-up 20rps / sale 80rps / peak 150rps / recovery 60rps), `RequestCohort`
- `capacity-model.ts` — `effectiveCapacity = replicas × base × health`, utilization, the latency-multiplier ladder + overload-error ladder (spec §10.5 formulas verbatim)
- `latency-model.ts` — edge base+jitter, payment provider normal(350–700ms)/peak(1400–3000ms) + post-timeout completion
- `retry-model.ts` — gateway timeout → retry policy → semantic identity carried per attempt (spec §10.7)
- `request-identity.ts` — `LogicalCheckout` + `NetworkAttempt`, duplicate detection on logical identity
- `idempotency.ts` — idempotency replay rule (spec §10.9): stable key + service support + unexpired → return stored result
- `data-integrity.ts` — unique-constraint rule (spec §10.10): conflict → map to existing order, not 500
- `queue-model.ts` — at-least-once redelivery, fulfillment dedup by orderId (does NOT cause duplicate charges — makes "queue did it" wrong)
- `manual-retry.ts` — 35% post-timeout manual retry; shares identity only if stable attempt ID present
- `cost-model.ts` + `complexity-model.ts` — abstract units per spec §10.13/§10.14
- `simulate-case.ts` — pipeline orchestrator (validate → topology → traffic → route cohorts → capacity → retry → integrity → queue → aggregate → objectives → report)
- `report-builder.ts` — metrics, event timeline with human timestamps + reason codes
- **Tests (spec §28 invariants):** same seed+arch = byte-identical report; replicas change capacity not duplicate semantics; unsafe retry without idempotency increases duplicates; stable key reduces them; unique constraint blocks duplicates; disable-retries lowers dup rate but raises failures; queue redelivery ≠ duplicate charges; metrics in valid ranges; p50≤p95≤p99; counts consistent; sim computes <100ms
- **Exit gate:** baseline reproduces the incident; correct design passes; scaling-only fails for the right reason

## Phase 8 — Simulation playback + outcome review
- `components/game/SimulationPlayer.tsx` — precomputed playback frames from the (already-calculated) report; **never recalculates**. Request pulses along edges, 1×/2×/skip, reduced-motion path.
- `MetricsPanel.tsx` — checkout/latency/errors/duplicates/cost live readouts + text summary for SR
- `EventFeed.tsx` — timestamped reason-coded events
- `OutcomeReview.tsx` — objective pass/fail, before-vs-after, root-cause verdict, positive effects, new/residual risks, change cost, complexity impact, suggested next step; actions: Revise / Investigate more / Roll back / Accept

## Phase 9 — Scoring + debrief
- `lib/game/domain/scoring/score-case.ts` — 1000-pt breakdown (spec §11.2); root-cause accuracy, objective achievement (partial credit by distance bands), investigation efficiency (base 40% + 60% unused-points), change-budget efficiency vs curated solution family, complexity discipline, reliability margin, tradeoff recognition, first-run bonus
- `objective-evaluator.ts` — passing thresholds (dup-order <0.05%, dup-charge <0.02%, success ≥97%, p95 <3.0s, cost ≤ budget)
- `feedback-builder.ts` — fact-based feedback from reason codes (spec §29 examples), not generic praise
- `DebriefPanel.tsx` — score, rank label (Principal Archaeologist…Case Reopened), correct root-cause explanation, evidence chain, why changes worked, why tempting alternatives failed, residual hardening steps, "view ideal solution" (post-completion), replay
- Persist completion

- Simulation logic 100% pure, UI has no formulas
- Seeded RNG everywhere, deterministic
- Case validated at load with field-path errors

- Discriminated-union configs, no `any` in domain contracts
