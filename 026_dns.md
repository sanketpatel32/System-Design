# DNS

> **Category:** Networking Basics

---

DNS = **Domain Name System** — translates human-readable hostnames (`google.com`) into IP
addresses (`142.250.190.46`). It's a hierarchical, distributed, eventually-consistent database.

### Hierarchy
```
Root nameserver (".")        13 logical, anycast globally
   |
TLD nameserver (".com")      per top-level domain
   |
Authoritative nameserver     per registered domain (e.g., example.com)
```

### Record types
| Type | Meaning |
|------|---------|
| A    | hostname → IPv4 |
| AAAA | hostname → IPv6 |
| CNAME| alias to another hostname |
| MX   | mail server |
| TXT  | arbitrary text (SPF, verification) |
| NS   | authoritative nameserver for a zone |
| SOA  | start of authority (zone metadata) |
| SRV  | service locator |
| PTR  | reverse lookup (IP → name) |

### Resolution flow
```
Browser -> OS resolver -> recursive resolver (ISP/Google 8.8.8.8)
         -> root -> TLD -> authoritative -> answer
```
Caches at each level via **TTL** (typically 300-3600s).

### Why it matters in design
- **DNS is eventually consistent** — TTL delays propagate changes.
- **DNS-based load balancing** (Route 53) can do weighted, geo, failover routing.
- **DNS is a SPOF** — keep TTLs short, use multiple resolvers, monitor resolution time.
- **DNSSEC** signs records to prevent spoofing.

### Gotchas
- Long TTL → fast resolution, slow failover.
- Short TTL → fast failover, more resolver load.
- Split-horizon DNS: different answers inside vs outside the corp network.

### Key takeaway
DNS is the first lookup in every request. Understand TTLs, hierarchy, and how DNS-based routing
(Route 53 weighted/geo) enables multi-region failover.
