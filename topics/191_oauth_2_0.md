# OAuth 2.0
> **Category:** Security

---

### Overview
**OAuth 2.0** is an open authorization framework that allows third-party applications to obtain limited access to user resources on an HTTP service without exposing user credentials. It delegates authorization from the resource owner to an authorization server.

### Authorization Code Flow with PKCE Architecture

```
Client App                 Authorization Server             Resource Server
(Browser/Mobile)               (Identity Provider)             (API Server)
    |                                   |                            |
    | --- 1. /authorize (PKCE Challenge)-> |                            |
    | <--- 2. Redirect with Auth Code -- |                            |
    |                                   |                            |
    | --- 3. /token (Code + Verifier) -> |                            |
    | <--- 4. Access Token (+ ID Token)- |                            |
    |                                                                |
    | --- 5. GET /resource (Header: Bearer <AccessToken>) ---------> |
    | <--- 6. Return Protected Resource Data ----------------------- |
```

### Grant Types & Use Cases

| Grant Type | Target Client Type | Security Mechanism | Standard Use Case |
|---|---|---|---|
| **Authorization Code + PKCE** | Public (Mobile, SPA) & Confidential (Server) | Dynamic Cryptographic Proof (`code_verifier`) | Single Page Apps, Native Mobile Apps, Web Apps |
| **Client Credentials** | Machine-to-Machine (M2M) | Confidential Client ID & Secret | Internal Microservices, Cron jobs, Daemon Services |
| **Device Authorization** | Input-constrained devices | User Code entry on secondary browser | Smart TVs, CLI tools, Game Consoles |
| **RefreshToken** | Client storing Refresh Token | Exchange refresh token for fresh access token | Maintaining user sessions without re-login |

### Token Architecture

| Token Type | Purpose | Format | Lifetime |
|---|---|---|---|
| **Access Token** | Authorizes API request execution | Commonly JWT or Opaque string | Short (5 - 60 minutes) |
| **Refresh Token** | Obtains new Access Token upon expiration | Opaque String (Stored securely) | Long (Days to Months) |
| **ID Token (OIDC)**| Contains authenticated user profile identity | Standard JWT | Instant consumption |

### Key Security Vulnerabilities & Mitigations
1. **CSRF on Auth Code**: Use `state` parameter or `PKCE` bound to client session.
2. **Authorization Code Interception**: Mandate **PKCE (Proof Key for Code Exchange)** for all public clients (RFC 7636).
3. **Token Exfiltration**: Store tokens in `HttpOnly`, `Secure` cookies or secure mobile keychains (iOS Keychain / Android Keystore).

### Key takeaway
**OAuth 2.0** is an authorization framework, not an authentication protocol (use OIDC on top of OAuth for AuthN). Always enforce **Authorization Code with PKCE** for user-facing applications and **Client Credentials** for server-to-server microservices.
