# DNS

> **Category:** Networking Basics

---

The **Domain Name System (DNS)** is the hierarchical, distributed phonebook of the Internet. It translates human-readable hostnames (e.g., `api.example.com`) into machine-routable IP addresses (e.g., `93.184.216.34` or `2606:2800:220:1:248:1893:25c8:1946`).

### Recursive DNS Resolution Hierarchy

```
+-------------------------------------------------------------------------+
|                  RECURSIVE DNS LOOKUP ARCHITECTURE                      |
+-------------------------------------------------------------------------+

  [ Client Browser ]
         |
         | (1. Query api.example.com)
         v
  [ Local DNS Resolver ] (ISP / 1.1.1.1 / 8.8.8.8)
         |
         +---( 2. Query Root "." )-------------> [ Root DNS Server ]
         |    <---( Return TLD ".com" IP )-------+
         |
         +---( 3. Query TLD ".com" )-----------> [ TLD DNS Server ]
         |    <---( Return Authoritative IP )----+
         |
         +---( 4. Query Authoritative )--------> [ Authoritative DNS ]
              <---( Return A Record: IP )-------+
```

### Core DNS Record Types Reference

| Record Type | Purpose | Example Value | Use Case |
| :--- | :--- | :--- | :--- |
| **A Record** | Maps domain name to IPv4 address. | `example.com -> 93.184.216.34` | Primary web server routing |
| **AAAA Record** | Maps domain name to 128-bit IPv6 address.| `example.com -> 2606:2800:220::1` | Modern IPv6 routing |
| **CNAME Record** | Maps alias hostname to canonical domain name.| `blog.example.com -> hash.cdn.com` | CDN and third-party aliases |
| **MX Record** | Directs mail to domain email servers. | `example.com -> mail.google.com` | Email delivery routing |
| **NS Record** | Identifies Authoritative DNS servers. | `example.com -> ns1.cloudflare.com` | DNS delegation |
| **TXT Record** | Holds arbitrary text metadata. | `v=spf1 include:_spf.google.com` | Domain ownership, SPF/DKIM security |

### DNS Routing & Load Balancing Strategies

1. **GeoDNS (Latency Routing)**: DNS server inspects client IP subnets (EDNS Client Subnet) and returns the IP of the physically nearest data center.
2. **Weighted Round-Robin DNS**: Returns multiple IP addresses in rotated order with specific weight ratios to distribute traffic across server pools.
3. **Anycast DNS**: Multiple DNS servers worldwide advertise identical IP addresses using BGP (Border Gateway Protocol). Routers automatically send packets to the nearest network hop.

### DNS TTL & Caching Behavior
Every DNS record carries a **TTL (Time To Live)** in seconds (e.g., TTL = 300). Caches store records until TTL expires. Low TTLs enable fast failover (e.g., 60s for active-passive failover), while high TTLs reduce DNS query traffic and latency.

### Key takeaway

DNS maps domain names to IP addresses via a recursive hierarchy (Root -> TLD -> Authoritative). Use **GeoDNS and Anycast** at the DNS layer to direct users to the nearest data center and achieve high-availability global load balancing.
