# TLS (Transport Layer Security)
> **Category:** Security

---

### Overview
**Transport Layer Security (TLS)** is the standard cryptographic protocol designed to provide privacy, endpoint authentication, and data integrity over a computer network. Operating above the Transport Layer (TCP) and below the Application Layer (HTTP), TLS secures communications using asymmetric encryption for key exchange and identity verification, and symmetric encryption for fast data transfer.

Modern architectures rely on **TLS 1.3** (RFC 8446), which streamlined the connection handshake from 2 round-trips (2-RTT) down to 1 round-trip (1-RTT) and mandated Perfect Forward Secrecy (PFS).

### TLS 1.3 Handshake Sequence & Key Exchange Diagram

```
CLIENT                                                              SERVER
  |                                                                    |
  | 1. ClientHello                                                     |
  |    + Supported TLS Versions (TLS 1.3)                              |
  |    + Key Share (ECDHE Public Key Params)                           |
  |    + Cipher Suites (AES-256-GCM, CHACHA20-POLY1305)                |
  | -----------------------------------------------------------------> |
  |                                                                    |
  |                                 2. ServerHello                     |
  |                                    + Selected Cipher Suite         |
  |                                    + Server Key Share              |
  |                                    + {Encrypted Extensions}        |
  |                                    + {Certificate + Verify}        |
  |                                    + {Finished Message}            |
  | <----------------------------------------------------------------- |
  |                                                                    |
  | [Client Verifies Certificate & Calculates Shared Symmetric Key]     |
  |                                                                    |
  | 3. {Client Finished}                                               |
  | -----------------------------------------------------------------> |
  |                                                                    |
  | <======= 1-RTT Complete: Encrypted Application Data (HTTP) =======>|
```

### Protocol Comparison: TLS 1.2 vs TLS 1.3

| Cryptographic Capability | TLS 1.2 | TLS 1.3 |
|---|---|---|
| **Handshake Latency** | 2 Round Trips (2-RTT) | 1 Round Trip (1-RTT) / 0-RTT (Resumption) |
| **Key Exchange Mechanics** | Static RSA, DHE, ECDHE | Mandatory Ephemeral Diffie-Hellman (ECDHE / X25519) |
| **Perfect Forward Secrecy (PFS)**| Optional (Config-dependent) | Strictly Enforced (Mandatory) |
| **Insecure Primitive Support** | Supports RSA key exchange, CBC ciphers, RC4, SHA-1 | Removed static RSA, CBC mode, RC4, MD5, SHA-1 |
| **Encrypted Handshake Meta** | Certificate transmitted in plaintext | Server Certificate & Extensions fully encrypted |

### X.509 Certificate Storage & Validation Schema

| Field Name | Cryptographic Function | Description |
|---|---|---|
| `Subject Name` | Domain Identity | Domain name (e.g., `*.api.example.com`) owning the public key. |
| `Issuer Name` | Trust Anchor | Digital signature of Certificate Authority (e.g., Let's Encrypt, DigiCert). |
| `Public Key` | Asymmetric Primitive | Elliptic Curve (secp256r1/Ed25519) or RSA 2048/4048 key. |
| `Validity Period` | Revocation Boundary | `NotBefore` and `NotAfter` timestamps (typically max 90 days). |
| `SAN (Subject Alt Name)`| Multi-Domain Binding | List of additional subdomains authorized by this certificate. |

### Architectural Trade-offs

| Strategy / Choice | Advantages | Disadvantages | Best Used When |
|---|---|---|---|
| **TLS Termination at Edge (L7 Balancer)** | Offloads CPU-heavy decryption from internal microservices; simplifies certificate management. | Unencrypted HTTP traffic flows over internal datacenter network (unless mTLS is used). | Standard public web applications and API gateways. |
| **Mutual TLS (mTLS)** | Guarantees mutual cryptographic authentication for both client and server microservices. | High certificate rotation overhead and CPU overhead across internal microservice nodes. | Zero-Trust service mesh architectures (Istio, Linkerd). |
| **TLS 1.3 0-RTT Early Data** | Eliminates handshake round-trip entirely for returning connections. | Vulnerable to Replay Attacks if applied to non-idempotent HTTP POST/PUT operations. | Latency-critical read-heavy endpoints (HTTP GET). |

### Key takeaway
**TLS 1.3** secures network communications by enforcing Perfect Forward Secrecy through ephemeral ECDHE key exchange, encrypting handshake metadata, and reducing connection establishment latency to a single round-trip (1-RTT).
