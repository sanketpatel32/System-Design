# API Keys

> **Category:** Security

---

API keys = **long-lived secret tokens** identifying a client (usually server-to-server).

### Use cases
- Server-to-server authentication.
- Third-party API access (Stripe, GitHub).
- Partner integrations.
- Service accounts.

### Format
- Opaque: `sk_live_abc123...` (server looks up info).
- JWT: signed token with claims.
- Random + hashed at rest.

### Issuance
- Generated by the provider.
- Stored hashed at rest (like passwords).
- Sent to client once (display, copy, never again).

### Rotation
- Keys leak. Rotate regularly (90 days typical).
- Support multiple active keys (overlap during rotation).
- Hard revoke on compromise.

### Scoping
- Per-key permissions (read-only, specific endpoints).
- Per-key rate limits.
- Per-key environment (test, prod).

### Transmission
- **Never in URLs** (logged everywhere).
- In `Authorization: Bearer` header.
- Over HTTPS always.

### vs OAuth
| | API key | OAuth |
|--|---------|-------|
| Use case | Server-to-server | User-delegated |
| Lifetime | Long | Short |
| User context | None | Yes |
| Revocation | Manual | Token expiry |

### Management
- **Secret manager** (AWS Secrets Manager, Vault).
- **Not in code** / git.
- Auto-rotation where possible.
- Audit logs of key usage.

### Key takeaway
API keys authenticate non-interactive clients (servers, jobs). Store hashed, transmit over
HTTPS in headers, rotate regularly, scope tightly. Use a secret manager — never commit keys to
git.
