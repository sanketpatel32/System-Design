# RPC

> **Category:** Networking Basics

---

RPC = **Remote Procedure Call** — calling a function on a remote machine as if it were local.
It abstracts the network away.

### How it works
```
Client calls     orderService.Create(...)
        |
client stub  --[serialize args]-->  network
                                       |
server stub  --[deserialize, dispatch]-> actual function
        |
return value  <--[serialize result]--  network
```

### Common RPC frameworks
| Framework | Encoding | Typical use |
|-----------|----------|-------------|
| gRPC      | Protocol Buffers (binary) | Microservices, internal APIs |
| Apache Thrift | Binary | Legacy, Facebook |
| JSON-RPC  | JSON | Lightweight web |
| GraphQL   | JSON | Client-curated queries |

### gRPC specifics
- **HTTP/2** underneath → multiplexing, header compression.
- **Protocol Buffers** schema → strongly typed, compact, cross-language.
- **Streaming** (server, client, bidi) — better than REST for real-time.
- **Code generation** — stubs in Go, Java, Python, etc.

### RPC vs REST
| | RPC (gRPC) | REST |
|--|-----------|------|
| Style | Action-oriented (`CreateOrder`) | Resource-oriented (`POST /orders`) |
| Encoding | Binary (protobuf) | JSON/text |
| Schema | Strict (.proto) | Loose (OpenAPI optional) |
| Performance | Fast, low-bandwidth | Slower, human-readable |
| Browser support | Needs grpc-web proxy | Native |
| Best for | Internal services | Public APIs |

### When to use RPC
- **Internal microservices** — strict schema, high throughput.
- **Streaming** workloads — live updates, bi-directional.
- **Polyglot stacks** — codegen gives type safety across languages.

### Key takeaway
Use gRPC for **service-to-service** inside the boundary (speed, schemas). Expose REST or GraphQL
at the edge for browsers and external clients. A common pattern: gRPC internally + REST gateway
externally.
